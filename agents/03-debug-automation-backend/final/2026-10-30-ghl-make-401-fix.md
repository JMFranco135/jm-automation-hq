# Fix Note: GHL → Make Webhook 401 Unauthorized

**Issue:** GoHighLevel workflow webhook returning 401 Unauthorized to Make.com
**Date:** 2026-10-30
**Client Type:** Home Services / Local Service Business

## Root Cause
GHL workflow configured to send custom header `X-API-Key` with token, but Make webhook module is configured to validate `Authorization: Bearer` header. Header mismatch causes 100% rejection.

## Fix Applied (Smallest)
1. In GoHighLevel Workflow → Webhook Action → Headers:
   - Remove header `X-API-Key: {{API_KEY}}`
   - Add header `Authorization: Bearer {{MAKE_WEBHOOK_TOKEN}}`
   - Keep `Content-Type: application/json`

2. Verify token value matches Make scenario Webhook → Copy URL → Token portion after `/`

## Test to Verify
1. Create test contact in GHL with email `test+debug@example.com`
2. Check GHL Workflow History → confirm webhook returns 200 OK
3. Check Make scenario Execution History → confirm module ran and Google Sheets row created
4. Check Google Sheets → verify test contact appears with correct fields

## Prevention
- Document header names in SOP for each integrator
- When rotating tokens, update both GHL and Make in same change window
- Enable Make webhook email alerts for 401 errors
